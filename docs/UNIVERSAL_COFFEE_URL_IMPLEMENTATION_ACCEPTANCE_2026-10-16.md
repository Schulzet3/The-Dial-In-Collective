## Canonical reason and user-facing rule

A member may add any real coffee to their **personal** library with two required facts, Name and Roaster. The member may paste an HTTPS URL, review suggestions, correct errors, fill gaps, and click **Add Coffee**, then immediately Log Shot → Rate → Recommendation. **No admin approval is required for that personal action.** A publicly shared **Verified** coffee has a higher trust threshold: exact official roaster/coffee/harvest or uniquely compatible canonical evidence. A member's confirmation is a useful personal fact confirmation, **not independently sufficient to amend public community facts**. Trusted official-source verification occurs automatically where evidence supports it; otherwise a new nonadmin coffee is usable privately as Pending. Existing roaster aliases, URL/release cross-checks, confirmed fuzzy matches, original shot IDs and audit requirements remain Locked and unchanged.

## Development code delivered (no production publish)

- `src/server/coffee-url-guard.mjs`: public HTTPS outbound reader with hostname/port/password restrictions, DNS lookup pinned **at TLS socket connection** instead of a vulnerable standalone DNS preflight, private/loopback/link-local/reserved IPv4 rejection including mixed DNS A answers, TLS SNI/certificate checks, zero forwarded user cookies/JWT/API keys, capped 900,000-byte body, 11-second request deadline, bounded compression, and up to 2 separately revalidated HTTPS redirects. It does not fetch scripts or allow an internal network destination. IPv6-only destinations, sites requiring login, bot challenges, and JavaScript-only content remain graceful fallback cases rather than disabling security.
- `src/server/coffee-page-metadata.mjs`: best-effort schema.org Product JSON-LD, merchant JSON, OG metadata, single product H1 with plausible product path, labeled definition/table/paragraph facts, focused explicit Wuri-style variety, process, elevation, origin and comma-delimited tasting notes, plus directly labeled **roaster espresso recipe** (dose/yield/time range), without inventing unavailable harvests or roast levels. All results are suggestions and escaped in HTML; a published espresso recipe is displayed as reference, **not yet persisted/applied as a recipe**, so no false canonical recipe provenance.
- `netlify/functions/coffee-url-preview.mjs`: Netlify `POST /api/coffee-preview` function with **real Supabase user JWT** validation, email-verified/admitted membership RPC, owner-bound server-side quota claim RPC, request-origin/method/body validation, and a separate, bounded remote fetch. Uses only Supabase public URL/publishable key, never service-role key or arbitrary user token to the roaster website. Returns `verification:'unverified'` and never calls canonical approval API.
- `supabase/migrations/20261016235900_dic_universal_coffee_preview_quota.sql`: separate RLS-denied app-private per-account attempt table and authenticated SECURITY DEFINER quota claim. **60 generic URL previews per confirmed admitted member per day, 3-second minimum cooldown**, separated from the old *trusted official preview* engineering limits (25/day, 12 seconds) to avoid retry double-throttling. Existing independent trusted-source verification limit remains unchanged. New quota numbers are implementation anti-abuse/cost safeguards, **not Locked UX requirements**; monitor and adjust on actual beta load. The SQL migration is **not applied to production** yet.
- `site/cloud/client.js`, `site/cloud/main.js`, `site/cloud/coffee-url-autofill.js`: retain the fast curated official preview for known roasters; safely fall back to generic extraction for unknown/metadata-poor or unavailable pages without reducing membership/security checks. **Autofill From URL fills available blank fields immediately**, preserves typed values, and presents a compact, editable unverified/official-source preview. The member then presses **Add Coffee**; canonical matching remains server-enforced. No new mandatory wizard or repeated Apply click.

The separate existing source verifier `supabase/functions/dic-verify-coffee/evidence.mjs` is extended to accept **exactly one matching product H1** on a *previously trusted official hostname and supported /products/{slug} path* as evidence if richer structured product markup is absent. A suspicious multiple-H1 page, mismatched name or different harvest fails; footer/copyright year does not establish a release. ## Security/cost boundaries

- All generic website content is **untrusted**; no arbitrary website receives an account JWT/API key, no untrusted content can approve Verified or replace a community canonical ID, no additional user input is required to read their own pending coffee, and missing details remain blank. URL preview quota and Netlify IP rate limiting are separate safety layers.
- Initial deterministic extraction makes **zero Claude/OpenAI API calls** and consumes **zero AI tokens**. A real deployed Netlify function uses the project's **Netlify compute, requests and bandwidth credits**, and Supabase Auth/RPC/DB usage falls within its platform allowances; user BYOK Claude credits are not used. Netlify's published credit model bills serverless compute and web traffic, not each preview as an AI request. The Locked optional **Claude V1 / device-local BYOK** remains **not implemented in this new generic extraction patch**; it may improve unusual unstructured pages later only with the existing key-privacy policy. No paid scraping provider or new subscription was created.
- Supporting provider billing reference: `https://docs.netlify.com/manage/accounts-and-billing/billing/billing-for-credit-based-plans/how-credits-work/`.
