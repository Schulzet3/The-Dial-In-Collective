Continue to obey GitHub private Free advisory CI and all existing Locked data safeguards. See decision OPS-AUTONOMOUS-BUILD-TEST-QUEUE-20261022, Issue #70 comment 6347498805.


**Source of truth.** GitHub (`Schulzet3/The-Dial-In-Collective`) is the authoritative record of product decisions, code, testing, deployments, approvals, failures, and unfinished work. The Master Specification and Decision Ledger govern requirements. Preserve every Locked decision and all historical/user data. Change a decision only with my explicit approval; record its exact scope and superseded requirement in both canonical files. Never treat brainstorming or a proposal as approval. Ask product questions one at a time. Keep the app sleek and optimized for **Log Shot → Rate → Recommendation**.

**Start every session with recovery.** Before making changes, read `AGENTS.md`, the active GitHub work journal, `docs/CURRENT_STATUS.md`, the Master Specification, Decision Ledger, approval coverage register, relevant open issues, and recent CI. Verify the latest `development/backend-foundation` commit and any interrupted or unverified work. `main` is the backup/operations branch, not the application source. Verify the actual Netlify published commit and other relevant provider state separately. Do not rely on chat history or an old handoff in place of live GitHub evidence.

**Document work as it happens.** As soon as I give a substantive instruction, capture its scope, approval status, planned action, and next step in GitHub before doing unrelated work. After each meaningful investigation, change, test, error, or provider action, update the journal and relevant issue/status with evidence and an exact next action. Every code, test, or CI change must include a contemporaneous journal entry **in the same Git commit**. Confirm every write by reading back the commit SHA and changed files. Never leave essential decisions or progress only in a chat. Do not commit credentials or private user records.

**Fail safely after interruption.** If a connection, tool, or chat fails, the next session must resume from the last **verified** GitHub commit, inspect pending/failed work, and reconcile before proceeding. If GitHub is unavailable or a write cannot be verified, stop external mutations and clearly identify anything not durably recorded. Never claim that text lost before it reached GitHub can be recovered or that continuity is 100% guaranteed.

**Verify, don't assume.** Track each approved change separately as **Approved → Implemented → Tested → Deployed → Accepted**, with affected screens, tests, source SHA, production SHA, and actual owner/device evidence. A passing source test does not prove a deployed feature works. Never mark incomplete, simulated, or inaccessible checks as verified. Audit for forgotten approvals and record gaps in GitHub.

**Protect releases and data.** No production release, Netlify credit spend, SQL/Edge/Auth/member-data mutation, provider-setting change, or paid purchase without my separate explicit approval. One release approval is usable only once and is tied to its unique ID and tested source SHA. Preserve backups, shot history, offline data, and original records. Ordinary commits use `[skip netlify]`. Never publish merely because code is ready.

**GitHub account constraint.** Keep the repository **private on GitHub Free**. Do not recommend or initiate GitHub Pro, a paid upgrade, or making it public unless I explicitly reconsider. Required status checks and branch protection are **not enforced** on our current private plan; GitHub Actions checks are advisory and can detect failures but cannot prevent all direct pushes. Use the existing review checks, same-commit journal, serialized release controller, single-use grant and non-force Git operations as compensating controls. Keep production publishing blocked until the remaining available safeguards and provider configuration are independently verified and I explicitly authorize the release. Report residual risks; never describe these controls as guaranteed or fully protected.
