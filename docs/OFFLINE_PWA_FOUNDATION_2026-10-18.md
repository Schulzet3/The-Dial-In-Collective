## Previous gap and target
The prior production app already persisted new shot events, receipts and read-only owner snapshots in IndexedDB, but a true browser cold restart without internet could not load its own cached JS/HTML, and connection setup queried remote admission before restoring a previous owner cache. The original offline support/product promise in the [Master Specification](MASTER_SPECIFICATION.md) §31 is cached coffees, local shot logging/rating, auto synchronization later; canonical coffee lookup, Community, administration and source/AI calls remain online-only. No new offline administrator rights or cross-member public caching are approved.

## Remaining limitations and acceptance gates
1. **Real device not tested:** genuine iPhone Safari/Add to Home Screen installation and app update behavior, cold reopen after airplane mode, multi-day offline session expiry, storage pressure/eviction, Home Screen/WebKit session behavior and two-device conflicts (#22/#26) remain **UNVERIFIED**. The manifest currently uses an SVG icon. Platform-specific PNG/touch icon and home screen installability need actual acceptance; do not claim all platforms support this manifest identically.
2. **Offline session intentionally conservative:** when the Supabase local SDK session is expired, absent, or switched, offline cold reopen fails closed until reconnect. This may restrict extended-duration airplane-mode use. It does not mean previously queued data was deleted. If the owner wants longer offline use after local credential expiry, it needs a separately reviewed trust/privacy design before relaxing the guard.
3. **Local at-rest privacy:** preexisting per-owner IndexedDB cache/queue contains data on the device; this work does not introduce cryptographic encryption at rest or a device unlock mechanism. The SW itself caches *zero* member records. Do not promise security against someone with access to unlocked device storage.
4. **Update model:** fingerprinted SW waits for older tabs to end; the old installed shell can remain in existing tabs until next controlled activation. A future non-intrusive update-available/refresh experience should be evaluated with pending writes and stale sessions before broad launch. Never force reload or discard unsynced changes.
5. **Provider/live checks still needed:** genuine admitted/revoked/other-member authenticated SDK HTTP behavior, read-only Community/card privacy evidence, background Auth token refresh semantics, and failure/retry are separate from this synthetic suite. Server RLS, admission and mutation guards remain authoritative. Additional early-access tests must not manufacture permanent production shots or bypass the owner release gate.
