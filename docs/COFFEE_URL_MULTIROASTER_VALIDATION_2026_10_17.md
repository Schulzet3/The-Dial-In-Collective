## Design and security invariants

- Existing authenticated, admitted-member, one-click 12-claim/24h quota and 30-second shared cooldown untouched. GitHub Actions public-page checks used no account or Supabase preview quota.
- HTTP retrieval uses the same existing pinned-DNS, HTTPS-only, no-unsafe-redirect, bounded 900 KB source guard. **Do not weaken those protections for an oversized storefront**.
- Extractions are suggestions labeled **Unverified Page**. They are not trusted Official Verified promotions, do not create or merge global coffee identities, and are only applied after member review. No guesses based on roaster brand, Agtron number, promotional text, unrelated product carousel, or unlabeled graphic endpoints.
- Existing canonical New Coffee fields (name, roaster, origin, elevation, roast level, process, variety, producer, tasting notes, harvest/release) remain clean and optional. Extra source facts (Agtron, rest days, production roaster, roast season, drying method, preferred extraction, processing detail) appear in an optional disclosure and are not silently written into unsupported canonical fields.
- Published Espresso recipes are reference-only, not applied to member shots or user defaults. A ratio without a dose/yield/time remains a ratio reference, not a fabricated recipe.
- Original seven owner-Locked Title Case roast levels, five named-coffee target assignments, legacy Light-Medium alias, old category recipe priors, Pending Wuri isolation, and all shot/community data remain intact.
