## Decision-quality protocol — permission-gated, future-only

**Stage 0 (authorized now):** static/source-only feasibility, precise confounder and case definitions; no server/user/provider reads, no new event fields, consent UI, instrumentation, interventions, cohort or experiment. No inferred numerator, denominator, consent or quality outcome. Retain existing app behavior.

**Stage 1 (NOT authorized now):** owner would have to explicitly approve a separate privacy review and optional, freely reversible, clearly explained member consent *before* any personal diary, opt-in observation, on-device analysis, export or member-data read. Prefer member-controlled voluntary diary/local review of existing private shots over service telemetry. No new production account, automated prompts, server sync, identifier upload, provider write or data retention assumption. Separate authorizations for any UI/storage/schema and data use, with #96 review and a complete opt-out/deletion policy. Explicitly distinguish privacy consent from a member's routine shot logging.

**Candidate unit:** one prospectively, knowingly recorded suggestion for shot A, followed by a shot B, where the member affirmatively confirms whether they attempted *that exact single-control recommendation*. Use no automatic acceptance inference from physical measurements. To be a *controlled comparable pair*, both shots must have the same private coffee identity and selected release if known, setup version, grinder calibration, basket, shot style (Turbo ≠ Fast-Flow), feed mode (including known Standard vs Slow), hardware and recipe context, and valid chronologically ordered timestamps; neither may be a hidden/duplicate/unsafe imported record or uncommitted conflicting edit. Require full five explicit 1–5 taste ratings **on both** A and B. Preserve original observations and notes and never overwrite either history row. If temperature is unrecorded, treat it as **unknown confounder**, not “unchanged.” Reject unknown feed/style/grinder alignment rather than guessing.

**Exposure and control:** record the exact suggestion `{prior-shot/version, source/version, one named controllable input, proposed value, member confirmed followed?}` only if separately authorized. Eligible intentional control is **one** of grind setting, measured target yield, dose or manually controllable temperature; time is an *outcome*, not an independently adjusted control. Hold the other measurable controls at their actual A values (and same basket/feed/style/calibration). An observed discrepancy without prospective confirmation is merely **changed setting**, not proven following advice. Distinguish engine no-op/all-green, diagnostic distribution advice, unexecutable settings, advice not seen, member declined, and missing exposure. Preparation-only interventions are not automatically comparable to quantitative one-control changes.

**Outcomes, all reported rather than collapsed:** for extraction/body compare distance from Locked midpoint 3; for clarity/sweetness compare movement toward 5; for astringency compare movement toward 1. Per scale classify **toward / unchanged / away** from its Locked ideal, plus original and next 1–5 values. Separately report five-green before/after and any worsening scale, even when other scales improve. This is an *ordinal within-member descriptive proxy*, never a measured cup-quality, causal, statistical confidence or scientific optimum claim. Do not conflate a member's preference with objective chemical extraction. Preserve outliers and adverse outcomes, including increased dryness, bitterness, sourness, lower clarity/sweetness, time/range violations and negative self-report.

**Confounding and uncertainty:** roast age/release, bean dose freshness/moisture, water recipe and pressure, unlogged grind calibration, machine thermal drift, tamp/WDT/puck distribution, basket geometry, retention, grinder feed, temperature, number of intermediate shots, tasting order/expectation bias, palate fatigue, scaling ceiling, self-selection, missing feedback and regression to mean. Record only **explicitly volunteered** controls/context if separately approved; never silently add required member fields or infer them from names/notes. No universal “improvement rate” from selectively complete pairs; show eligibility, exclusion reason and missingness by style, setup and recommendation type. Never pool unlike setups or same-person coffees as independent experimental replication. A later shot can be satisfying for different reasons even with an identical control.

### Reproducible competing hypothetical cases (NOT measured outcomes)

| Case | Proposed classification |
| --- | --- |
| A: explicit single grind adjustment; same identified coffee/setup/calibration/basket/style/feed; same measured dose/yield/temperature; A+B all five rated | **Candidate described pair** after opt-in and prospective action confirmation; no causal conclusion |
| B: same known context and single target-yield adjustment; observed time changes | Time is an observed response; candidate only if other actual controls unchanged and prospective confirmation exists |
| C: temperature absent in either shot, or setup temperature control disabled | **Unknown temperature confounder**; not strictly matched; do not call unchanged |
| D: Slow Feed switches on between A and B, or Turbo becomes Fast-Flow, or new grinder calibration | **Exclude cross-context**; new context baseline, not a single-change test |
| E: one missing rating, invalid imported physical measurement, date missing or pending offline duplicate | **Ineligible or pending**, never count as a failed taste response; preserve original History |
| F: A already all five green; engine recommends no action | **No intervention**. Valid app success, not an “improvement” trial |
| G: “Use Recommendation” copied initial grind but no verifiable prior Next Shot recommendation exposure | **Starting-reference provenance only**; not next-shot recommendation acceptance |
| H: member changes grind and yield together or changes preparation | **Multiple/confounded changes**; report separately, not single-control effectiveness |
| I: suggestion declined or never viewed, or A→B happened without an archived recommendation version | **No confirmed exposure**; do not fill an adoption denominator with a guessed acceptance |
| J: one scale improves but another worsens | **Mixed outcome / adverse movement retained**; no aggregate “improved espresso” assertion |
