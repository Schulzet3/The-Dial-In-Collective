## 3. Mandatory future "Publish" decision tree

This is a procedural clarification of already-LOCKED #417/#457 policy, **not** new release or product authorization.

1. **Recover exact truth, not chat assumptions:** read development/backend-foundation, main and release/production refs, AGENTS, applicable journal, current queue/approval coverage/Locked decisions, consumed grants and request, latest Netlify published/current deployment, backup evidence and live owner scope. Detect concurrent release work first.
2. **Freeze the approved batch:** map the current instruction to exact READY IDs and independently verified *required approved dependencies*. A separate READY added by hourly work remains excluded; any owner-authorized increase 25→27→28 is a **new exact source/IDs batch**, not reuse of old candidate/authorization.
3. **Cheap source isolation and dependency check BEFORE full CI:** derive published-baseline-to-selected deployable diff. Verify all selected Git objects equal approved READY merged source; all excluded READY/unfinished runtime and relevant tests restore exact published bytes; import/export and cross-item dependencies resolve; no unready same-file overlap or unapproved SQL/Auth/Edge/member-data changes. Reject missing symbols, inconsistent queue ownership, changed scopes and historic-SHA fixture assumptions. If uncertain **BATCH_BLOCKED** with precise repair action.
4. **Stage only after explicit publish instruction:** source-isolate with existing READY-only planner, append SAME-COMMIT candidate journal/manifest, and keep unfinished development intact. Use BATCH_PREPARING, BATCH_BLOCKED or BATCH_RELEASE_READY correctly. A READY *item* does not certify a *batch*.
5. **Exact candidate evidence:** require all five status jobs (approval, validate, cloud-tests, mobile-browser-qa, sql) successful **for the pinned candidate SHA**. Inspect actual applicable tests; distinguish SKIP, NOT_APPLICABLE, running and FAIL. Repair real CI failures narrowly; reuse tests/builds that are valid for unchanged identical source—never duplicate the full suite just because publishing was requested.
6. **Recovery, provider and one-use preflight:** reuse valid encrypted offsite/recovery receipts and check SQL risk. Extra backup only before actually potentially destructive approved DB work. Check live expected main/development/release SHAs, owner approval, exact selected IDs, unexpired and unused source-bound grant, schema-v4 request, Netlify production routing and one available publisher. No Netlify credit screenshot/balance gate; report only actual provider quota refusal.
7. **Working default publication route:** create exactly **one** one-parent **nonforce** main commit whose **only** changed files are docs/RELEASE_REQUEST.json and the same-commit append-only main ops journal, message **ops(release-request): ID [skip netlify]**. That GitHub push triggers [dic-chat-approved-release.yml](https://github.com/Schulzet3/The-Dial-In-Collective/blob/main/.github/workflows/dic-chat-approved-release.yml); **no direct workflow_dispatch connector call is necessary**. Existing guarded controller checks grant/refs/checks/backup, consumes the one-use grant, serializes ONE nonforce release/production claim and causes ONE Git-connected Netlify build. No direct immutable/API publisher, parallel publisher, force or replay.
8. **If a GitHub tool write fails or is blocked:** before any permitted retry, read back main request commit, current refs, grant consumption, GitHub controller run and Netlify. If no write occurred, preserve the certified candidate and unconsumed grant; observe expiry and concurrent drift. A legitimate fallback is the **owner-run** existing [dic-single-use-release.yml](https://github.com/Schulzet3/The-Dial-In-Collective/blob/main/.github/workflows/dic-single-use-release.yml) with **fresh schema-v4 evidence** bound to current refs and the same controller, only when eligible and not already consumed. A platform safety prohibition must not be bypassed; describe actual blocker/next permitted actor and never claim DEPLOYED.
9. **Postflight before queue promotion:** independently match live production Git SHA and Netlify READY/current commit_ref to release grant; check expected functions/routes, deployable blob fidelity, SQL/Edge changes if any, read-only DB continuity and published source backup pin. Record one-use consumption, release CI and provider receipts. Promote **only proven delivered** IDs to DEPLOYED; preserve newer READY and unfinished work; reconcile journal, status, queue, issue. No production synthetic user tests or second build to re-prove a successful Git-connected deploy.

### Failure → bounded recovery

| Condition | Specific action |
| --- | --- |
| Old release hash in a test | Rebind test against current queue and published Git objects; targeted regressions and necessary exact-source candidate checks. Never mark a real FAIL as cosmetic. |
| READY import depends on TESTING code | Independently verify/promote required dependency or safely remove dependency with tests. HOLD until source complete. |
| New unrelated READY appears while staging | Keep owner snapshot; exclude entire unrelated deployable scope, including new tests, to published bytes; HOLD on overlap. |
| CI job running or SKIPPED | Wait/read specific job or record NOT_APPLICABLE; no false PASS, grant or build until required evidence. |
| Platform rejects a GitHub write | Verify no partial mutation; preserve evidence, use only permitted existing paths. Do not bypass OpenAI policy or forge controller trigger. |
| Connector lacks workflow_dispatch | **Not** a blocker to approved one-parent two-file main push. Manual native GitHub workflow is fallback, not primary. |
| Netlify READY/current mismatch or GitHub claim uncertain | STOP postflight; inspect actual provider/controller; no automatic second build, replay or queue promotion. |
| Queue changed during settlement | Reread live ref and settle only delivered IDs with nonforce integration; preserve all concurrent other work. |
